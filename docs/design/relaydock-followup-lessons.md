# Archived composition lessons — 2026-09-30

Generalized from a separate product's layout follow-up. Private timings, token counts, session IDs, unrelated product details and inaccessible evidence links were removed for public documentation. Historical product tests/screenshots are not reproduced here. This is not a current product or shared UI release audit.

- Reusing a Header does not keep navigation stable when route-specific parent widths differ. Separate the application frame from purpose-specific content widths and compare affected routes under matching viewport/language/theme conditions.
- Choose frame widths using actual tasks and sparse/dense content. Another product's numeric cap is not a shared token.
- Columns respond to available content space. Check long/localized labels, cell wrapping, local scrolling and touch areas as well as page overflow.
- Report functionality, shared-design compliance and visual composition separately. Tests and code review do not replace comparable screen inspection.
- Preserve prior contrast, nested-control and touch findings until current measurements close them. Later layout work did not establish those unrelated fixes.
- Installation does not prove a long-running agent loaded the new workflow. Record the revision and hashes actually read.

These lessons informed the dated [composition verification](common-design-compliance-verification.md), [dual review](frontend-v2-dual-review.md) and maintained [consumer guide](v2-migration.md). The historical product is outside shared package acceptance.
