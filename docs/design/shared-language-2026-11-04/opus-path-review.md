# URL 통일안 — Opus 5.5 리뷰 반영

## 보완본 재검토

[보완본 응답](opus-path-review-recheck.md)은 B1/B2 해결을 확인하고, 첫 운영 수신 배포 실패의 rollback 경로를 명시하라는 조건을 남겼다. 무접두사 의미를 4단계에 확정한 대안과 cache key 검증 판단은 수용했다.

북마크 갱신을 운영 acceptance 직후로 옮기고 auth login/return이 4단계라는 설명을 채택했다. 다만 “북마크 갱신 전에는 외부 locale 링크가 없으므로 옛 앱으로 복귀 가능”이라는 제안은 채택하지 않았다. 로컬 선택기·legacy redirect·직접 입력으로 이미 새 경로를 사용할 수 있기 때문이다. §11은 최초 운영 노출 전 별도 복귀 경로 확보를 요구하며, 무트래픽 격리 배포 실패와 노출 후 실패를 구분한다.

[마지막 응답](opus-path-review-final.md)은 이 반론을 수용하고, 호환 빌드가 없을 때 안전한 구버전보다 서비스 전체503을 우선한 점을 지적했다. 이 지적은 채택했다. 최종 §11/§12는 호환 빌드를 정상 복귀로 우선하고, 불가능하면 새 prefixed 경로에서 보호 데이터 없이404인지 사전에 확인한 구버전으로 긴급 복귀를 허용한다. 이미 locale 경로를 지원하는 메인은404를 요구하지 않고 기존 auth 경계 유지를 확인한다. 긴급 복귀는 언어 계약 실패·기본 경로 의미 역전·완료 철회로 기록하며, 그 구버전도 안전하지 않을 때만503을 사용한다. 이로써 언어 계약 유지를 위해 서비스 가용성을 불필요하게 포기하는 우선순위를 제거했다.

마지막 응답은 이 수정 조건으로 승인한다는 결론이다. 작업자가 해당 수정과 관련 문장/인수 항목을 반영했다. 최종 바이트를 다시 무조건 승인받았다고 기록하지 않는다. 모델 identity·검토별 hash·최종 문서 hash는 [기계 기록](path-review-receipt.json)에 있다.

문서상의 설계 검토는 제품의 상태 보존·인증·번역 실행 검증을 대신하지 않는다.
