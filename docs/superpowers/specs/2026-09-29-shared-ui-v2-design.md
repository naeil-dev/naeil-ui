# 공통 디자인 시스템 v2 설계

상태: 시각 방향 검토 완료. 확정한 방향을 실제 패키지에 연결하는 설계서이며, 구현 계획과 제품 코드 변경은 아직 진행하지 않았다.

## 1. 목적과 범위

여러 제품이 같은 규칙의 버튼·입력창·메뉴·팝업을 가져다 쓸 수 있도록 `@naeil/ui`를 개선한다. 결과물은 디자인 규칙, 생성 가능한 디자인 토큰, React 공통 컴포넌트, 실제 컴포넌트로 만든 검토 화면, 사용 지침이다.

naeil.dev의 페이지 구성, 동물 이미지, 3D 장면, 히어로, 패러글라이더 커서는 이번 공통 디자인 범위에 포함하지 않는다. 기존 사이트는 호환성 확인에 사용한다. 공통 컴포넌트 변경에 따라 색·글자·크기가 달라질 수 있지만, 사이트의 콘텐츠나 레이아웃을 별도로 재설계하지 않는다.

v2는 이번 개선 작업의 이름이다. npm 배포 버전 변경, 패키지 게시, 사이트 배포는 이번 설계 승인에 포함하지 않는다.

## 2. 사용자가 선택한 기본 규칙

| 항목 | 선택한 방향 |
| --- | --- |
| 참고 구조 | Linear의 정돈된 위계·표면·간격. 브랜드 색은 의무가 아니다 |
| 색 | 무채색 액션과 선택 배경. 성공·경고·오류는 의미 색 유지 |
| 글꼴 | 한글·영문 Pretendard, 일본어 예시 Noto Sans JP |
| 본문·입력·버튼 | 16px, 약 25px 줄 높이 |
| 보조 설명 / 메타정보 | 14px / 13px |
| 읽기 본문 | 16px, 약 30px 줄 높이. 일반 UI보다 넓게 |
| 제목 | 페이지 32px, 섹션 20px, 컴포넌트 16px; 주로 600 굵기 |
| 콘텐츠 최대 폭 | 읽기 640px, 설정 640px, 작업 목록 1,200px |
| 폭의 예외 | 짧은 폼 480px, 열이 많은 데이터 화면은 가용 폭 전체 |
| 기본 간격 | 컨트롤 40px, 목록 행 최소 72px, 폼 내부 24px, 필드 사이 24px |
| 촘촘한 간격 | 필요한 정보 화면에 한해 컨트롤 36px, 행 최소 60px, 폼 내부 20px, 필드 사이 16px |
| 작은 화면 | 입력·버튼 및 터치 영역 최소 44px, 예시 목록 행 최소 72px |
| 모서리 | 태그 4px, 컨트롤 8px, 패널·다이얼로그 12px |
| 움직임 | 색·메뉴 120ms, 팝업·알림 180ms. 튀는 효과 없이 짧게 |
| 움직임 줄이기 | 사용자 설정이 켜져 있으면 전환·공간 이동을 생략 |

폭은 콘텐츠 바깥 테두리의 최대값이다. 화면이 작으면 사용 가능한 공간으로 줄인다. 640px 설정 폼을 넓은 설정 페이지 안에 넣을 수 있으며, 전체 앱을 무조건 640px로 제한하는 규칙은 아니다. 긴 내용은 줄바꿈하거나 높이가 늘어날 수 있어야 한다.

기본 간격을 우선하며 밀도를 바꿔도 글자 크기는 줄이지 않는다. 아이콘 버튼과 체크박스의 그림 크기와 클릭 가능한 영역 크기를 구분한다.

## 3. 현재 코드에서 해결할 차이

| 현재 확인한 상태 | 설계 결정 |
| --- | --- |
| `src/tokens/*.json`에서 `dist/theme.css`를 생성하지만 패키지는 `src/styles/theme.css`를 내보낸다 | 실제 배포 CSS를 토큰에서 생성하고, 대비 검사도 그 CSS를 읽는다 |
| `tsup`이 `dist`를 비운다 | 배포 CSS의 기준 출력은 `src/styles/theme.css`로 유지해 패키지 빌드의 정리 작업과 충돌하지 않게 한다 |
| 폰트 크기·그림자 등은 토큰과 컴포넌트 값이 일치하지 않는다 | 색·글꼴·크기·간격·폭·모서리·그림자·움직임을 같은 생성 경로로 연결한다 |
| Input은 데스크톱에서 글씨를 줄이고, Button 기본 높이는 36px다 | 승인한 16px / 기본 40px 규칙으로 변경한다 |
| 버튼 축소, 다이얼로그 확대·축소와 배경 흐림이 있다 | 짧은 색/불투명도 변화로 정리한다. 전역 `transition-all`을 피한다 |
| 언어 선택·스위치·체크박스가 시안에는 있지만 공개 공통 컴포넌트에는 없다 | 기존 Radix 기반으로 Select·Switch·Checkbox를 추가한다 |
| 공개 globals.css에 사이트용 float 애니메이션이 포함된다 | 공통 globals와 사이트 전용 스타일을 분리한다 |
| 대비 검사가 색을 읽지 못해도 경고 후 통과할 수 있다 | 필수 값 누락·해석 실패를 검사 실패로 처리한다 |

## 4. 토큰과 CSS 구조

`src/tokens/*.json`이 수치의 단일 원본이다. `scripts/build-tokens.ts`가 Tailwind 4 연결과 light/dark 변수를 포함하는 `src/styles/theme.css`를 생성한다. 생성 파일에는 직접 수정 금지 표시를 넣고, 재생성했을 때 차이가 없는지 검사한다. 기존 TypeScript 토큰 출력은 유지하되, 빌드 순서와 패키지에 포함할 산출물을 명시한다.

기존 `@naeil/ui/theme.css` 경로를 유지한다. 기존 소비 코드가 사용하는 `primary`, `primary-foreground`, `background`, `card`, `popover`, `ring` 등의 이름은 의미에 맞게 새 역할에 연결한다. 액션, 포커스, 선택 배경을 하나의 색 변수로 합치지 않는다. 기존 프로젝트 색은 호환성을 위해 남기되 공통 액션 색으로 사용하지 않는다.

기본 색은 선택한 무채색 시안 값을 사용한다. 읽을 수 있는 보조 글씨와 비활성 스타일을 구분한다. 오류 문구, 오류 배경, 파괴적 행동 버튼은 서로 다른 사용 목적에 맞는 전경·배경 쌍을 갖는다. 모든 필수 조합은 검증 대상이다.

light/dark는 기존 ThemeProvider 및 `.light`/`.dark`와 호환한다. 명시적 선택이 OS 테마보다 우선한다. 테마를 지정하지 않은 경우에만 OS 설정을 따른다.

첫 구현의 밀도는 문서 루트 `data-ui-density="comfortable|compact"`로 정한다. 설정하지 않으면 comfortable이다. 포털로 표시되는 메뉴와 다이얼로그도 같은 변수를 사용한다. 중첩된 독립 밀도 영역 API는 이번 범위에 추가하지 않는다.

콘텐츠 폭은 용도별 토큰과 간단한 CSS 사용 예로 제공한다. 새로운 범용 레이아웃 프레임워크나 업무용 작업 목록 컴포넌트를 만들지 않는다.

## 5. 공통 컴포넌트 범위

| 대상 | 변경과 동작 |
| --- | --- |
| Button | 기존 variant/size/asChild 유지. 무채색 행동 위계, 16px 기본 글씨, 밀도·비활성·포커스 정리. 로딩 예시는 기존 props와 `aria-busy`로 구성 |
| Input | 16px 유지, 필드 경계·포커스·오류·비활성 정리. 레이블과 도움말/오류 연결 예시 제공 |
| Card / CardElevated | 기존 exports 유지. 패널·올라온 표면·그림자 역할 구분. 기본 hover나 클릭 동작을 정적 Card에 추가하지 않음 |
| Dialog | Radix 포커스 가두기·Esc 닫기·포커스 복귀 유지. 불투명 표면과 짧은 전환, 작은 화면에서 넘침 없이 표시 |
| DropdownMenu | 행동 메뉴로 유지. 하위 메뉴·체크/라디오 항목·키보드 동작과 기존 exports 보존 |
| Badge | 정상·성공·경고·오류 표시. 색 외에도 텍스트나 아이콘으로 의미 전달 |
| Avatar | 이미지·fallback·그룹 exports 유지. 크기·글꼴·표면을 기준에 맞춤 |
| Toaster | Sonner 기반 유지. 상태별 의미, 읽을 수 있는 텍스트, 전환과 reduced-motion 정리. 위치·시간 등 소비자의 override 유지 |
| Select (추가) | Radix Select 기반 단일 값 선택. Trigger/Value/Content/Item 등 조합형 API, controlled/uncontrolled와 name/required/disabled 지원 |
| Switch (추가) | Radix Switch 기반. checked/defaultChecked/onCheckedChange와 form 연동 지원 |
| Checkbox (추가) | Radix Checkbox 기반. checked/indeterminate, 키보드·레이블·form 연동 지원 |
| 제목·테마 컨트롤 | PageTitle/SectionTitle과 공통 테마 컨트롤에 같은 글꼴·크기·포커스 규칙 적용 |

Select는 값을 고르는 입력이며 DropdownMenu는 행동을 고르는 메뉴다. 언어 선택을 DropdownMenu로 대체하지 않는다. Select는 트리거 폭에 맞는 메뉴, 선택 표시, 화면 경계 회피, 스크롤 가능한 옵션, 방향키·문자 탐색·Esc·포커스 복귀를 지원한다. Radix의 `position="popper"`와 제공되는 크기 변수를 이용해 승인한 배치를 맞춘다.

폼 저장, 검색, 작업 생성 같은 업무 로직은 예시 화면이 담당한다. 라이브러리 컴포넌트가 서버 통신이나 프로젝트 데이터를 소유하지 않는다. 처음 추가하는 세 컴포넌트는 시안에서 이미 확인한 재사용 필요에 한정한다.

## 6. 호환성과 폰트 전달

기존 루트와 `/ui`, `/utils`의 공개 이름을 제거하지 않는다. Nav/Footer/Logo는 이번 작업에서 브랜드 데이터나 구조를 재설계하지 않는다. 변경되는 기본 크기·색과 소비자가 명시적으로 덮어쓴 클래스의 관계를 이전 안내에 기록한다.

`/components/*`, `/lib/*`, `/i18n/*` 깊은 import는 현재 export 선언과 실제 npm 포함 파일이 일치하는지 확인하고, 선언된 경로가 패키지 안에서 해석되도록 맞춘다. 기존 경로를 아무 설명 없이 지우는 방식으로 해결하지 않는다.

`@naeil/ui/globals.css`는 공통 기본 스타일을 가리키게 한다. 사이트 앱은 공통 CSS와 자기 전용 float 스타일을 별도로 불러온다. 소비 앱에 사이트 애니메이션을 강제로 배포하지 않는다. CSS의 번들 제거를 막도록 `sideEffects`에 CSS 경로를 명시한다.

패키지가 자동으로 외부 폰트 서버에 접속하도록 만들지 않는다. 소비자가 Pretendard와 필요한 일본어 폰트를 직접 호스팅하거나 자신의 폰트 전달 방식을 선택하도록 문서화한다. Storybook은 실제 폰트를 로드해 재현 가능한 기준 화면을 제공한다. 폰트를 못 불러오면 시스템 fallback을 사용한다. 코드용 폰트는 기존 fallback 체계를 유지하며 새 글꼴 구매나 설치를 요구하지 않는다.

## 7. 검토 화면과 완료 조건

Storybook에서 실제 공개 컴포넌트로 설정 폼, 읽기 화면, 목록/상세 화면을 구성한다. 각 화면은 light/dark, 기본/촘촘한 밀도, 한글·영문·일문과 긴 문장을 포함한다. 시안 HTML만 유지한 채 패키지가 완성됐다고 판단하지 않는다.

완료 조건:

- 토큰을 재생성해도 배포 CSS에 설명 없는 차이가 없고, 패키지 빌드 이후 필요한 산출물이 모두 남는다.
- 실제 배포 CSS의 본문 대비는 4.5:1, 큰 글씨와 필수 컨트롤/포커스 표시는 3:1 이상이다. alpha 합성, hover, 선택, 오류도 검사한다.
- 마우스·키보드로 메뉴, Select, Dialog, Switch, Checkbox를 조작할 수 있다. 포커스가 보이고 적절한 위치로 돌아온다. 닫힌 콘텐츠는 탭 순서에 남지 않는다.
- 로딩·빈 화면·실패·재시도·성공을 같은 예시에서 확인할 수 있다. 오류가 입력 내용을 지우지 않고 비동기 상태가 보조 기술에 전달된다.
- reduced-motion을 실제로 에뮬레이션해 전환과 알림/로딩 동작을 확인한다.
- 390px와 데스크톱에서 레이아웃을 확인한다. 페이지 전체의 불필요한 가로 스크롤은 없고 넓은 데이터 표만 내부 스크롤을 허용한다.
- 자동 접근성 점검과 키보드 확인을 통과한다. 자동 검사만으로 전체 접근성 검증을 완료했다고 쓰지 않는다.
- `build:tokens`, 대비 검사, 관련 동작 테스트, lint, 패키지 빌드, Storybook 빌드 및 실제 소비 예시의 import/CSS 사용을 확인한다. 기존 사이트 빌드로 호환성도 확인한다.
- 실제 패키지 tarball에 공개 import 경로와 필요한 CSS·문서가 포함된다. 로컬 소스 참조만으로 소비 테스트를 대신하지 않는다.

| 21st.dev | 아직 사용하지 않음. 기존 Radix 조합으로 설명되는 범위여서 새 시각 컴포넌트를 가져올 필요 없음 |
| Impeccable polish/distill | 도구를 실행하지 않음. 구현 후 실제 결과의 일관성·불필요한 장식·접근성을 점검하는 마무리 단계가 남아 있음 |

따라서 Threads에 나온 모든 도구를 실행한 상태는 아니다. 이 절차를 수행하기 위한 전용 스킬이나 플러그인을 새로 만드는 것도 이번 결과물에 포함하지 않는다.

루트 `DESIGN.md`는 사람이 읽고 AI도 참고하는 사용 규칙으로 유지한다. 이 문서는 패키지 변경 범위와 검증 기준을 정의한다. 구현 시 소비자 안내와 저장소 작업 지침에서 두 문서와 실제 공개 API를 연결한다.
