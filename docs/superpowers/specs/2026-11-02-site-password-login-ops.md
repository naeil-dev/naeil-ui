# S2 deployment gates

Do not enable production credential/email-link actions until the owner records these checks. These are gates, not verified hosted settings.

- GoTrue v2.197 `conf/configuration.go:RateLimitHeader` supports `GOTRUE_RATE_LIMIT_HEADER`; `api/middleware.go:performRateLimiting` also consumes the validated `sb-forwarded-for` context when `GOTRUE_SECURITY_SB_FORWARDED_FOR_ENABLED` is true (default false). This proves source support, not Supabase hosted gateway/header trust. The site does not forward client-controlled X-Forwarded-For or assert that a Vercel IP header survives hosted Auth.
- Required fallback: owner-configured Vercel Firewall rate limiting by the platform's actual client IP, initially 10 requests/60 seconds with a 60-second block, on naeil.dev POSTs with the Next-Action header on **any path**, plus POSTs under `/login`, `/en/login`, `/ko/login`, `/ja/login` and their change-password pages. Include alternate-route action-ID requests so URL aliases cannot bypass the rule. This covers password, email-link and reauthentication-code actions. Verify two independent IPs have separate buckets, forged forwarding headers do not change identity, and recovery/logout remain usable. No process-memory/serverless limiter is provided. If verified hosted IP forwarding later replaces this gate, document the trusted header, gateway overwrite/authentication behavior and two-IP probe first.
- Test the existing Home SQL008 fences/audit contract, real Auth password/current-password policy, reauthentication-code delivery, SMTP and Google/GitHub separately. Secure password change needs the new request-code affordance; temporary reserved-domain accounts need a working delivery route or an owner-approved compatible Auth policy.
- GoTrue `token.go` checks user_banned before authenticating the password. SQL008 errors during `tokens/service.go:IssueRefreshToken` are wrapped as unexpected_failure, shared with unrelated faults. Every login error uses the same generic message; no email lookup, admin filter or sweep RPC is used. The authenticated change page can show explicit expiry from verified metadata.
- Valid email-link requests, nonexistent accounts and upstream errors share the response and a 1.5-second minimum response budget. This is a timing floor, not constant-time SMTP; verify slow-delivery timing under the Firewall rule before activation. Empty/malformed email is a local validation error and never requests Auth. The PKCE link must open in the browser that requested it; UI copy states this limitation.
- The private config master key derives distinct HKDF cookie/HMAC keys. No key, password or token belongs in logs. Verify final client bundles and actual production config without printing secrets. Merging redeploys the site; all S2 PRs remain drafts and unmerged here.
