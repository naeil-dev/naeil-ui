# Exact callback return — site local verification, 2026-10-18

Local implementation follows the [authorized plan](../plans/2026-10-18-exact-callback-return-plan.md) and unchanged [reviewed proposal](../specs/2026-10-18-exact-callback-return-design.md), SHA256 `7da4163bd9743ec75c599b4d214ceb33dc34ad0f7fc54f7fac79636c0a680a66`. This is an inert fixed-destination relay, without site session, transaction, exchange or grant authority. No hosted setting, real Auth request, mail, push, deployment or production process changed.

Implementation addendum: real Next16.1.7 HTTP tests proved that proxy and App Router `Request.url` values cannot meet the reviewed raw-query contract. Proxy adapter URLSearchParams serialization repairs invalid percent/UTF-8, canonicalizes encoded keys and strips internal fields; App Router preparation also filters and reserializes the query. `.rsc` is normalized before proxy. Two initial candidates preserved these failures; they are superseded rather than accepted as compliant.

The root authorized a narrow Pages API adapter after those findings. `next.config.ts` rewrites the public return namespace internally to `src/pages/api/internal/service-return.ts`. The adapter reads only the original server-owned `IncomingMessage` metadata through private `next/dist/server/request-meta`, checks the installed version is exactly `16.1.7`, and fails with protected503 if original metadata is missing or ambiguous. It never falls back to headers, `req.url`, `req.query`, cookies or body. Absolute metadata origins have no authority; exact relative original targets are supported. Its raw path is checked before any URL normalization. Direct internal API requests and aliases cannot relay. `IncomingMessage.rawHeaders` enforces exactly one literal `Host: naeil.dev`, including duplicate-host rejection.

The parser factory remains `createServiceReturnHandler({siteAuthority, destinations})`; it accepts a normal `Request`, or the structural `Pick<Request, "url" | "method" | "headers">` used by the trusted adapter to preserve raw bytes. Constructing a new Request first was rejected by regression tests: literal apostrophes expand and trailing spaces are trimmed, changing the16KiB boundary. No runtime destination override or test flag exists. Only the fixed three production callbacks are compiled into `serviceReturnHandler`.

The broad proxy matcher rejects encoded, locale, Next data/RSC, malformed-percent and internal-route aliases before site Auth/locale processing. Exact canonical GETs pass through to the original-metadata adapter. Unsupported methods return405 with `Allow: GET`, no Location and the same data-free security headers. Ordinary trailing-slash canonicalization runs after the protected namespaces; existing invitation, site callback, login and public routing remain covered by their tests. Conservative ASCII percent decoding is for namespace rejection only and cannot authorize a path.
