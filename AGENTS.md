- Read `DESIGN.md` before changing shared UI. The implementation scope is in `docs/superpowers/specs/2026-09-29-shared-ui-v2-design.md` and consumer guidance in `docs/design/v2-migration.md`.
- This repository contains both the shared `@naeil/ui` package and a website. Do not treat hero illustrations, 3D scenes, cursor effects, or product-specific content as shared design-system requirements.
- Numeric foundation values live in `src/tokens/*.json`. Generate `src/styles/theme.css` with `pnpm build:tokens`; do not hand-edit generated CSS. Shared globals and component behavior styles live in `src/styles/`; site-only styles stay in `src/app/`.
- Prefer existing public components and Radix behavior. Select is a value input; DropdownMenu is an action menu. Preserve public imports and consumer overrides unless a requested change explicitly revises the API.
- Application navigation and footer must use `NaeilHeader` with `NaeilFooter` from `@naeil/ui/naeil-footer` for owned naeil services, or `Navigation` with `SiteFooter` from `@naeil/ui/ui` for a different product without canonical naeil chrome. Consumers own menu data, routing/auth state and deliberate frame overrides, not copied menu/mobile/footer implementations. `Nav` and `Footer` retain the Next/next-intl compatibility APIs. Read `docs/components/application-layout.md` for the complete starter and copyable consumer-agent rules; `docs/components/navigation.md` and `docs/design/navigation-footer-integration.md` retain API and rollout details.
- Applications inheriting the actual naeil.dev header use the opt-in `@naeil/ui/naeil-header` composition (introduced in 0.5.0; shared frame defaults updated in 0.6.0). Do not copy its menu/control/toolbar/style implementation. Supply locale/routing/guard/auth state; keep content widths independent. Read `docs/components/naeil-header.md`. Generic Navigation remains for a different product without canonical naeil chrome. The canonical header references the single official `https://naeil.dev/images/whale.png` URL for the naeil-ui catalog; retain the network dependency and unresolved artwork redistribution limits in `THIRD_PARTY_NOTICES.md`, without bundling those image bytes.
- Owned Next services under the shared `NaeilLocaleProvider` import header/account/footer chrome from `@naeil/ui/naeil-locale/chrome`; `/naeil-header` and `/naeil-footer` remain standalone React adapters. Read `docs/components/naeil-locale.md` for `/naeil-locale`, `/client`, `/server`, `/messages`, `/checker` and `/chrome`, including controller lifetime, routing, messages and consumer guards.
- For layout changes, separate the product's application frame from purpose-specific content widths. Compare affected routes under matching viewport/language/theme conditions; shared component imports do not prove stable navigation. Follow the composition guidance in `docs/design/v2-migration.md` and retain unresolved prior findings until rechecked.
- Page rhythm (0.15.0): main regions use `.ui-app-frame ui-app-main` and pages start with `PageHeader`; theme defaults to dark (as naeil.dev), base text 16px, favicon links match naeil.dev. Do not add per-page top/bottom padding, per-site theme defaults or title sizes. See DESIGN.md "Page rhythm".

Keep reading/settings at 640px and short forms at 480px inside that frame. Do not wrap navigation/footer in another padded frame. Change numeric values in `src/tokens/ui.json` and preserve explicit consumer overrides.
- Verify relevant tests, contrast, the actual Storybook result, and packed consumption when changing package behavior. Do not claim external design tools were used unless they were actually run. Publishing and site deployment are separate from implementation.
