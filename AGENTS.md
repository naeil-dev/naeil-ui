# Shared UI work

- Read [STATUS.md](STATUS.md#current-state) for publication, Docs and service adoption status; keep current status only there. Preserve frozen release source, tags and archive/reference bytes. Do not repack maintained main or move a tag for guide updates; record npm, Docs and service rollout receipts separately. Check `package.json` and fresh registry metadata against reviewed main before release work. Service auto-merge is patch-only; deployment stays manual.

- Owned apps pass session state through shell `account`; the shell supplies `NaeilHeaderAccountControl` with its locale/Link. Shell `header.authSlot` is deprecated compatibility; standalone header uses `authSlot`. Supply the busy flag and guarded callback. Keep pending state and the request lock above the shell or standalone header so desktop/mobile copies share them. App-owned logout buttons or avatar-menu markup do not establish canonical header parity. Verify authenticated states as well as anonymous chrome.

- Read `DESIGN.md` before changing shared UI. The implementation scope is in `docs/superpowers/specs/2026-09-29-shared-ui-v2-design.md` and consumer guidance in `docs/design/v2-migration.md`.
- This repository contains both the shared `@naeil/ui` package and a website. Do not treat hero illustrations, 3D scenes, cursor effects, or product-specific content as shared design-system requirements.
- Numeric foundation values live in `src/tokens/*.json`. Generate `src/styles/theme.css` with `pnpm build:tokens`; do not hand-edit generated CSS. Shared globals and component behavior styles live in `src/styles/`; site-only styles stay in `src/app/`.
- Prefer existing public components and Radix behavior. Select is a value input; DropdownMenu is an action menu. Preserve public imports and consumer overrides unless a requested change explicitly revises the API.
- Owned-service application frames use `NaeilServiceShell` + root `NaeilThemeProvider`; pass menu state through `header` and session state through `account` and shared routing/save guards through `Link`/`onNavigate`. Generic `Navigation` with `SiteFooter` from `@naeil/ui/ui` remains for a different product without canonical naeil chrome. Consumers own menu data and routing/auth state; deliberate frame overrides remain available only in generic/legacy compositions. Do not copy menu/mobile/footer implementations. Standalone `NaeilHeader`/`NaeilFooter` and `Nav`/`Footer` retain their compatibility APIs. Read `docs/components/application-layout.md` for the complete starter and copyable consumer-agent rules; `docs/components/navigation.md` and `docs/design/navigation-footer-integration.md` retain API and rollout details.
- naeil.dev uses `NaeilServiceShell service="main"` for its no-suffix Projects/Blog catalog. Owned services use their service id with the same shell frame. Import `@naeil/ui/fonts.css`; applications do not install fonts, rebuild body defaults, or add viewport-height wrappers. Do not copy the menu/control/toolbar/style implementation. Supply locale/routing/guard/auth state; keep content widths independent. Read `docs/components/naeil-header.md`. Generic Navigation remains for a different product without canonical naeil chrome. The canonical header references the single official `https://naeil.dev/images/whale.png` URL for the naeil-ui catalog; retain the network dependency and unresolved artwork redistribution limits in `THIRD_PARTY_NOTICES.md`, without bundling those image bytes.
- Owned Next services under the shared `NaeilLocaleProvider` import shell/provider/PageHeader/account chrome from `@naeil/ui/naeil-locale/chrome`; `/naeil-shell` is the standalone React shell entry, while `/naeil-header` and `/naeil-footer` remain standalone React adapters. Read `docs/components/naeil-locale.md` for `/naeil-locale`, `/client`, `/server`, `/messages`, `/checker` and `/chrome`, including controller lifetime, routing, messages and consumer guards.
- For layout changes, separate the product's application frame from purpose-specific content widths. Compare affected routes under matching viewport/language/theme conditions; shared component imports do not prove stable navigation. Follow the composition guidance in `docs/design/v2-migration.md` and retain unresolved prior findings until rechecked.
- Page rhythm / service shell: owned services use `NaeilServiceShell` + root `NaeilThemeProvider` from `/naeil-shell` (standalone) or `/naeil-locale/chrome` (provider-backed), start pages with `PageHeader`, and run `naeil-ui-conformance --service <id> --framework next|vite --app <dir>` and runtime `naeil-ui-conformance --service <id> --url <origin> --routes /a,/b [--no-footer /login]` in CI (consumer-installed Playwright). Shell header inputs retain the documented compatibility inputs, but owned services pass account= instead of deprecated header.authSlot; runtime --no-account records matching login-page exceptions; navigation `labels` supplies accessible names. Do not rebuild frame/theme/base text/favicon policy, style reserved chrome selectors or add page padding/title sizes. Use server-safe `naeilIcons` and title helpers from `/naeil-locale`. Record any `footer={false}` screen or CLI ignore reason. See `docs/components/naeil-shell.md` and DESIGN.md "Page rhythm".
- Default frames are maximum 1600px with `clamp(16px, 2.4vw, 40px)` gutters. Owned services receive main's `.ui-app-frame ui-app-main` from the shell and do not apply those classes themselves; generic compositions use `.ui-app-frame` on main. Shared navigation/footer have built-in frames; do not wrap them in another padded frame. Keep reading/settings at 640px and short forms at 480px inside main. Change numeric values in `src/tokens/ui.json`; preserve supported generic/legacy overrides without applying them to the protected shell.
- Verify relevant tests, contrast, the actual Storybook result, and packed consumption when changing package behavior. Do not claim external design tools were used unless they were actually run. Publishing and site deployment are separate from implementation.
- Browser titles follow `Page name — Service name` (home/landing may use the service name alone). Use canonical `.naeil` / `.naeil <service>` derived from the service id (`localeMetadata`, `naeilDocumentTitle`), localize page names only, and use the shared brand-kit `.naeil` favicon on every route. Owned services receive the full canonical footer from the shell; `footer` uses `resolveHref` or `false` for a recorded no-footer screen. Owned services leave `meta` empty; the public `meta` prop remains for standalone/generic compatibility and existing consumers. Follow DESIGN.md's Browser identity and `docs/design/v2-migration.md`; metadata belongs to the consumer application, not implicit Navigation/Logo behavior.

- `html { scrollbar-gutter: stable }` is the shared page-frame default in `components.css`, reached by `globals.css` or `theme.css + components.css`. Set `<html data-naeil-scrollbar-gutter="auto">` before first paint to opt out of both reservation and lock correction. Custom body edge spacing/scrollers/helper-class compensation require consumer integration or opt-out. Theme-only and JS-only imports do not set document policy.
- Check classic and overlay probes, short/long frames and ordinary content through nested scroll locks; measure before any fullPage capture. Keep tokens unchanged during scrollbar-policy work and document narrow Japanese toolbar wrapping in both modes. See the adopted `docs/superpowers/specs/2026-10-29-page-root-scrollbar-gutter.md`; releases, main/site merge, hosted Docs and service upgrades need separate approvals.

## Frontend references

- For a new frontend page, a substantial design improvement, or an explicit mention of Refero, awesome-design-md, 21st.dev, Component Gallery, Kinetics, or Impeccable, read `skills/frontend-reference-workflow/SKILL.md` and follow its relevant route. Small copy/spacing/bug fixes use the existing system directly unless reference/tool use is explicitly requested.
- `DESIGN.md` remains the visual authority. External references fill identified gaps; generic Impeccable advice must not replace the approved neutral palette, Pretendard, purpose-specific widths, or restrained motion.
- Record adopted sources and actual tool usage in `docs/design/frontend-sources.md`. Environment/install status lives in `docs/design/frontend-tooling.md`; an installed/configured tool is not proof it was executed or authenticated.
