# Shared UI work

- The 0.7.1 release in progress adds `NaeilHeaderAccountControl` from `/naeil-header`. Owned apps put this shared login/account/menu presentation in `authSlot` and supply their session state, busy flag and guarded callback. Keep pending state and the request lock above `NaeilHeader` so desktop/mobile copies share them. App-owned logout buttons or avatar-menu markup do not establish canonical header parity. Verify authenticated states as well as anonymous chrome.

- The first intended published 0.7.x release is 0.7.1, including `@naeil/ui/naeil-footer` and `/release` from the unpublished 0.7.0 candidate. The current registry baseline is 0.6.0 until publication receipts confirm otherwise. Owned services use `NaeilHeader` with `NaeilFooter` for canonical destinations, preserving consumer routing/save guards. Generic Navigation/SiteFooter and legacy Nav/Footer remain public. See `docs/components/naeil-footer.md` and `docs/rollout/`; local candidate checks do not establish production convergence.

- Preserve frozen 0.7.1 archive/reference bytes and source `32108fd8e1cb1db6dae24a09f3ca72ac9a91f618`; its release tag is `v0.7.1`. Maintained Docs use a separately reviewed source. Do not repack current main or move the tag to incorporate guide updates; record npm, Docs and service rollout receipts separately.

- Read `DESIGN.md` before changing shared UI. The implementation scope is in `docs/superpowers/specs/2026-09-29-shared-ui-v2-design.md` and consumer guidance in `docs/design/v2-migration.md`.
- This repository contains both the shared `@naeil/ui` package and a website. Do not treat hero illustrations, 3D scenes, cursor effects, or product-specific content as shared design-system requirements.
- Numeric foundation values live in `src/tokens/*.json`. Generate `src/styles/theme.css` with `pnpm build:tokens`; do not hand-edit generated CSS. Shared globals and component behavior styles live in `src/styles/`; site-only styles stay in `src/app/`.
- Prefer existing public components and Radix behavior. Select is a value input; DropdownMenu is an action menu. Preserve public imports and consumer overrides unless a requested change explicitly revises the API.
- Application navigation and footer must use `NaeilHeader` with `NaeilFooter` from `@naeil/ui/naeil-footer` for owned naeil services, or `Navigation` with `SiteFooter` from `@naeil/ui/ui` for different product menus. Consumers own menu data, routing/auth state and deliberate frame overrides, not copied menu/mobile/footer implementations. `Nav` and `Footer` retain the Next/next-intl compatibility APIs. Read `docs/components/application-layout.md` for the complete starter and copyable consumer-agent rules; `docs/components/navigation.md` and `docs/design/navigation-footer-integration.md` retain API and rollout details.
- Applications inheriting the actual naeil.dev header use the opt-in `@naeil/ui/naeil-header` composition (introduced in 0.5.0; shared frame defaults updated in 0.6.0). Do not copy its menu/control/toolbar/style implementation. Supply locale/routing/guard/auth state; keep content widths independent. Read `docs/components/naeil-header.md`. Generic Navigation remains for different product menus. The canonical header references five official `https://naeil.dev/images/*.png` URLs; retain the network dependency and unresolved artwork redistribution limits in `THIRD_PARTY_NOTICES.md`, without bundling those image bytes.
- For layout changes, separate the product's application frame from purpose-specific content widths. Compare affected routes under matching viewport/language/theme conditions; shared component imports do not prove stable navigation. Follow the composition guidance in `docs/design/v2-migration.md` and retain unresolved prior findings until rechecked.
- Default frames use `.ui-app-frame` for main content and the shared navigation/footer's built-in frames: maximum 1600px with `clamp(16px, 2.4vw, 40px)` gutters. Keep reading/settings at 640px and short forms at 480px inside that frame. Do not wrap navigation/footer in another padded frame. Change numeric values in `src/tokens/ui.json` and preserve explicit consumer overrides.
- Verify relevant tests, contrast, the actual Storybook result, and packed consumption when changing package behavior. Do not claim external design tools were used unless they were actually run. Publishing and site deployment are separate from implementation.
- Browser titles follow `Page name — Service name` (home/landing may use the service name alone). Use canonical `.naeil` / `Naeil Home`, localize page names only, and retain the service favicon across routes. Follow DESIGN.md's Browser identity and `docs/design/v2-migration.md`; metadata belongs to the consumer application, not implicit Navigation/Logo behavior.

## Frontend references

- For a new frontend page, a substantial design improvement, or an explicit mention of Refero, awesome-design-md, 21st.dev, Component Gallery, Kinetics, or Impeccable, read `skills/frontend-reference-workflow/SKILL.md` and follow its relevant route. Small copy/spacing/bug fixes use the existing system directly unless reference/tool use is explicitly requested.
- `DESIGN.md` remains the visual authority. External references fill identified gaps; generic Impeccable advice must not replace the approved neutral palette, Pretendard, purpose-specific widths, or restrained motion.
- Record adopted sources and actual tool usage in `docs/design/frontend-sources.md`. Environment/install status lives in `docs/design/frontend-tooling.md`; an installed/configured tool is not proof it was executed or authenticated.
